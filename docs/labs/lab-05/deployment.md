## 1. Stack and changes from the reference

| Layer | MoneyLog | Reference (Starter Kit) |
|---|---|---|
| App | Node 24, Express 4 API + React 18/Vite SPA in **one image** on port 3000 (`SERVE_CLIENT=true`) | Same |
| ORM / DB | Prisma 5, PostgreSQL 16 → **Cloud SQL for PostgreSQL 16** | Same |
| Runtime | **Cloud Run** service `moneylog`, migration job `moneylog-migrate` | Same pattern |
| Images | **Artifact Registry** `asia-southeast1-docker.pkg.dev/<PROJECT_ID>/moneylog/moneylog:<commit SHA>` | Same |
| Secrets | **Secret Manager** (`moneylog-database-url`, `moneylog-admin-password`, `moneylog-demo-password`) | Same |
| CI/CD | **GitHub Actions** (`ci-docker.yml`, `deploy.yml`) + Workload Identity Federation | Same |

These are the differences from the kit, with the reason for each:
- **Sessions are already in the database** (Sprint 1, `Session` table). MoneyLog has no file uploads, so no container storage is needed (R-04).
- **The seed is compiled.** The migration job runs `node dist/seed/run.js`, so production never needs `tsx`.
- **The write Origin check accepts the app's own origin**, worked out from the `Host` / `X-Forwarded-*` headers. This way the Cloud Run URL works without knowing it before the first deploy. `CLIENT_ORIGIN` stays for the local Vite dev server.
- **The session uses a cookie**, not a bearer token. The smoke test signs in with a cookie jar.
- **`/api/version` reports `APP_COMMIT_SHA`.** The value is baked into the image at build time (`--build-arg GIT_SHA`), so a rollback also shows the right commit.

## 2. Environment variables

| Variable | Used by | Purpose | Secret? | Value comes from |
|---|---|---|---|---|
| `DATABASE_URL` | server, Prisma, migration job | PostgreSQL connection | **Yes** | Local `server/.env`; GCP: Secret Manager `moneylog-database-url` (unix socket `/cloudsql/<conn>`) |
| `PORT` | server | Listen port | No | `3000` (Dockerfile; Cloud Run `--port 3000`) |
| `NODE_ENV` | server | `production` in the image | No | Dockerfile / Cloud Run env |
| `CLIENT_ORIGIN` | server | Extra allowed `Origin` for writes (dev server) | No | `.env` locally; not needed on Cloud Run |
| `COOKIE_SECURE` | server | Adds the `Secure` flag to the session cookie | No | `true` on Cloud Run (deploy.sh) |
| `SERVE_CLIENT` | server | Express serves `client/dist` | No | `true` in the Dockerfile |
| `APP_COMMIT_SHA` | server | Commit shown by `/api/version` | No | Docker build arg `GIT_SHA` (pipeline: `github.sha`) |
| `ADMIN_PASSWORD` | migration job (seed) | First administrator `admin@moneylog.test` | **Yes** | Secret Manager `moneylog-admin-password` (generated by deploy.sh, never printed) |
| `SEED_DEMO_DATA` | migration job (seed) | `true` also creates demo users alice/bob/dave for UAT | No | deploy.sh `--demo` |
| `DEMO_USER_PASSWORD` | migration job (seed) | Password of the demo users | **Yes** | Secret Manager `moneylog-demo-password` (generated, never printed) |
| `POSTGRES_USER/PASSWORD/DB` | docker compose only | Local database container | Local only | Root `.env` (copied from `.env.example`) |

Every variable with a placeholder value is listed in `server/.env.example` and in the root `.env.example` (compose). `.env` is in `.gitignore`.
Pipeline values are GitHub **variables** (not secrets) in environment `demo`: `GCP_PROJECT_ID`, `GCP_REGION`, `WIF_PROVIDER`, `WIF_SERVICE_ACCOUNT`, plus optional `SMOKE_EMAIL` with **secret** `SMOKE_PASSWORD`.

## 3. Commands

| Task | Command |
|---|---|
| Install | `npm ci --prefix server && npm ci --prefix client && npm ci` |
| Migrate | `cd server && npx prisma migrate deploy` |
| Seed (dev) | `cd server && npm run db:seed` |
| Seed (image / job) | `npm run db:seed:prod` |
| Test | `npm test --prefix server`, `npm test --prefix client`, `npx playwright test` |
| Build | `npm run build --prefix server && npm run build --prefix client` |
| Run locally (containers) | `cp .env.example .env` → edit → `docker compose up --build` → http://localhost:3000 |
| Build the image | `docker build --build-arg GIT_SHA=$(git rev-parse HEAD) -t moneylog .` |
